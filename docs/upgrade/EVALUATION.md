## 1. 评测目标与设计原则

在 P0–P4 依次完成证据溯源、时间有效性、实体关系模型、Chat 认知提案流、Working 任务经验分离与 Coding 代码修订链后，P5 阶段将检索层与认知场景深度联通。

评测核心原则：
1. **真实可复现**：评测集与测试逻辑完全代码化（位于 `crates/retrieval/tests/eval_suite.rs`），杜绝任何伪造或未运行的数据；
2. **场景自适应**：支持按显式 `scene`（Chat / Working / Coding）定向召回并给予场景感知打分加成（+0.05），未指定 scene 时严格保持 100% 向后兼容；
3. **时间有效性断言**：事实演化后旧事实自动封堵有效截止期（`valid_until`），检索支持传入 `valid_at` 断言特定时间点的事实；默认排除已失效事实，请求 `include_superseded` 时降权呈现以供演化回溯；
4. **零泄漏安全门禁**：同名命名空间跨账户检索必须做到严格隔离，泄漏计数强制断言为 0；
5. **强健容灾降级**：向量服务故障降级至关键词 FTS，软超时（soft timeout）降级至列表兜底，保证检索永不无限期挂起。

## 3. 评测指标定义

> [!NOTE]
> 本节 §3.1 是 **eval_suite 冒烟口径（历史版本）**；**当前质量指标口径见 §7.2 与 §8**。
> 两套口径不要混用：§3.1 的 Recall@3 / MRR@5 属于旧的"6 大测试集"评测，
> 当前基准是 Bench v2（480 文档 / 600 查询，Recall@K / MRR@10 / nDCG@10）。

### 3.1 eval_suite 冒烟口径（历史版本）

1. **Recall@K (K=1, 3, 5)**：
   $$\text{Recall@K} = \frac{\text{目标条目排在前 } K \text{ 名的查询数}}{\text{总查询数}}$$
2. **MRR (Mean Reciprocal Rank)**：
   $$\text{MRR} = \frac{1}{|Q|} \sum_{i=1}^{|Q|} \frac{1}{\text{rank}_i}$$
3. **Cross-Account Leakage Count**：
   跨账户越权召回记录数（必须严格等于 0）。
4. **Fault Degradation Success Rate**：
   下游模型或数据库超时时的平滑降级成功比例（必须达到 100%）。

> **修订注记（2026-10-19，正确性修复后补记）：**
> - 上述输出中的样本数（7）与当前 `eval_suite.rs` 实际执行的 11 条查询不一致，文档数字早于样本扩充且未同步；
> - **Recall@5 = 100% 是结构性的**：每个命名空间只有 3–5 条记忆而 `top_k = 5`，必然全部命中；"召回"因此在很大程度上只在测关键词覆盖；
> - **故障降级成功率 100% 同样是结构性的**：成功计数在断言之后自增，任何失败都会 panic，不存在"测出 100%"的可能；
> - 评测已改用固定时钟（`eval_fixed_now = 2026-10-19`）：此前"现行有效"事实的 `valid_until` 硬编码为 2026-12-31，2027 年起该查询将无结果、门禁失败（时间炸弹），现已在任何日期运行结果一致；
> - 结论：以上数字只能作为管道连通性验证，**不得作为检索质量或场景能力的证据**。

> **第二步修订注记（2026-10-19，候选结构与打分模型改造后）：**
> - 候选池不再按 `updated_at` 截断：FTS 路按 `ts_rank_cd` 相关度取前 `HUB_RETRIEVAL_FTS_K`（默认 100），向量路取前 `HUB_RETRIEVAL_VEC_K`（默认 100）；
> - 词法层三处统一：FTS 由全词元 AND 改为部分匹配（OR）+ 相关度排序，`kw` 改为词元集合匹配 + 池内 IDF 加权（`api` 不再误命中 `rapid`，常见 bigram 去停用词）；
> - 打分维度调整：近期性改用事件时间（`occurred_at`）并按记忆类型区分衰减常数；第五维由"版本新鲜度"换为认知层级先验（`LayerPrior`）；
> - 因此本节历史指标与本文件其余数字**不可与新口径直接比较**，重建评测（第三步/第四步）需按新口径重新冻结基线。

## 5. 性能与延迟基线

- **评测环境：** Apple Silicon macOS (aarch64), 本地内存存储 (`InMemoryHubStore`) + 确定性 L2 归一化伪向量嵌入器 (`TestEmbedder`)。

### 7.2 指标与配对门禁

指标：Recall@1/5/10、MRR@10、nDCG@10、硬负例违规率（Top-3）、负控制命中率、进程内 p50/p95。

**门禁用逐查询配对检验**（不再比较两个独立的总体比例）：

- 基线文件保存每条查询的逐条结果（`per_query`），门禁按查询 id 配对，
  对每个指标计算 **配对差值 Δ、配对标准误 SE、z = Δ/SE**；
- 判定规则：**Δ 超过 1 个百分点且 |z| ≥ 2** 才算退化；两个条件缺一不可，
  避免"容差比噪声还小"导致的随机误报（独立比较下 600 条查询的标准误约 2 个百分点，
  配对后可降到 1 个百分点以内）；
- 分类别同样做配对门禁（类别样本 ≥30 才判定），任一类别退化都会点名报告；
- 配对样本覆盖率低于基线 95% 时直接判定"不可比"而不是静默比较；
- 数据集指纹或嵌入器不一致时会明确提示不可比，需重新冻结基线。

灵敏度已用注入回归验证：把 sim 权重从 0.50 调到 0.80、kw 从 0.20 调到 0.05 后，
门禁给出 Overall Recall@1 Δ −27.2pt（z = −14.1）、Recall@5 Δ −37.4pt（z = −18.0），
并同时点名 `env` 等类别的退化。

**结论（须在真实嵌入模型下复核后才可据此改默认参数）：**

1. **在伪向量环境下 sim 维度是纯噪声**：权重归零后 Recall@1 提升 **17.6 个百分点**
   （48.89% → 66.48%）、Recall@5 提升 21.3pt、MRR 0.5888 → 0.7838；
   kw 仍是唯一有效信号（归零后 Recall@1 跌至 20.19%）。
2. **部署实例当前正是 `HUB_EMBED_PROVIDER=mock`**（见 §7.5），生产检索同样处于
   "sim 权重 0.5 ≈ 噪声"状态。接入真实嵌入模型之前，可评估下调/置零 sim 权重作为临时缓解，
   但必须以真实模型基线下复核，不得用本节伪向量结论直接改默认值。
3. `paraphrase`（20.00%）、`env`（15.00%）与 `temporal`（18.33%）是主要短板：
   前两者只能靠真实嵌入模型改善；`temporal` 的**过滤正确**（硬负例违规率 0%）但排序被
   向量噪声压制，同样需要在真实模型下复测。
4. 其余信号（conf / rec / prior）在 600 条查询上的消融差异 ≤1pt，落在配对标准误内——
   说明在当前模态下它们既不有害也不可验证；Δ≤1pt 的差异不应作为调参依据。
5. MMR：λ=0.5 明显更差（Recall@5 −6.7pt）；λ=0.9 与 0.7 差异在噪声内。
6. 场景软偏好（prefer）总体略差（R@1 −0.74pt、R@5 −0.55pt），维持"默认关闭、待评测"。
7. 缺嵌入条目（`no_embedding`）Recall@1 = 100%：第一步"按可用信号归一化"的修复
   使无向量条目仍可被词法正确召回。

## 8. 语义能力显式化、默认拒绝阈值与三层门禁（第五步）

本节对应审计提出的两项 P0 与一项 P1：**不能把伪向量下的分数当作语义能力结论**、
**域外问题必须能被拒绝**、**业务语义约束要有独立的正确性门禁**。

### 8.1 语义能力变成系统的一等状态

`Embedder` trait 新增能力声明（`crates/mem-core/src/infra.rs`）：

```rust
/// 该嵌入器是否提供真实语义信号
fn provides_semantic_signal(&self) -> bool { true }
```

- `MockEmbedder`（生产默认的 mock 提供方）与 `TestEmbedder`（评测用）返回 `false`；
- `HttpEmbedder`（真实嵌入服务）保持 `true`。

系统据此做三件事：

1. **打分不掺噪声**：无语义信号时，向量维度按"不可用"处理，剩余维度重新归一化。
   **配置权重一个字都没改**——换成真实模型后该维度自动恢复参与，权重仍是配置值。
   这不是"永久调低语义权重"，而是"没有信号就不假装有信号"。
2. **健康检查如实声明**：`GET /readyz` 与 `GET /capabilities` 返回
   `semantic.ready` / `semantic.reason` / `embed.provider` / `embed.model`。
   启动时另有一条醒目告警。**"接口能返回结果"不再等于"语义检索可用"。**
3. **评测报告标注模态**：报告首行打印"语义能力：已就绪 / 未就绪"，
   基线文件落盘 `semantic_ready` 字段；设 `HUB_EVAL_REQUIRE_SEMANTIC=1` 时，
   伪向量嵌入器直接判失败——**用伪向量冒充语义验收结论不可能通过**。

### 8.2 默认拒绝阈值（域外问题的"无可靠匹配"）

之前检索没有默认 `min_score`：域外查询也能靠 FTS 部分匹配拿到结果，负控制命中率 100%。

现在：

- `HUB_RETRIEVAL_MIN_SCORE`（默认 **0.65**）在调用方未显式传 `min_score` 时生效；
- 低于阈值的候选一律丢弃；一条不剩时工具返回
  `{"results": [], "no_reliable_match": true, "reason": "..."}`——
  **明确说"没有可靠匹配"，而不是硬凑一条低分结果**；
- 可按场景单独配阈值（`HUB_SCENE_MIN_SCORE_PROFILES="chat=0.70;working=0.60"`），
  调用方显式传 `min_score` 优先级最高；
- **时间锚定查询（显式 `valid_at`）不叠加服务端阈值**：这类查询要的是"某个历史时点的事实"，
  它天然更旧、词法更弱，用按当下相关性标定的阈值去卡它，等于把正确答案挡在门外。
  同时近期性维度改以**参考时点**计算（此前一律按墙上时钟，把历史事实压到阈值之下）。

阈值由标定曲线确定（`HUB_EVAL_CALIBRATE=1` 可复现）：

| 阈值 | Recall@1 | Recall@10 | 域外误召回率 | Top-3 硬负例 | 首位误取率 |
| :--- | ---: | ---: | ---: | ---: | ---: |
| 0.00 | 68.33% | 97.59% | 100.00% | 15.19% | 0.56% |
| 0.60 | 68.33% | 97.59% | 15.00% | 15.74% | 0.56% |
| **0.65** | **68.15%** | **97.22%** | **0.00%** | 19.63% | 0.56% |
| 0.70 | 67.41% | 94.44% | 0.00% | 14.63% | 0.56% |
| 0.80 | 62.78% | 85.93% | 0.00% | 8.70% | 0.19% |

选取规则：**能把域外误召回率压到 0 的最小阈值**。更高的阈值继续压低 Top-3 硬负例占比，
但 Recall@10 掉到 85% 以下，属于"用召回深度换表面精度"，不划算。

> **该阈值是在伪向量（纯词法）模态下标定的。** 接入真实嵌入模型后 **必须重新标定**：
> 真实模型下 sim 维度参与打分，分数尺度会变。标定命令见 §8.4。

### 8.3 三层门禁：相对门禁不够用

| 层 | 判定依据 | 抓什么问题 | 与基线的关系 |
| :--- | :--- | :--- | :--- |
| 相对门禁 | 与冻结基线逐查询配对（Δ > 1pt 且 \|z\| ≥ 2） | 指标**退化** | 依赖基线 |
| 绝对门禁 | 域外误召回率 ≤ **10%**；首位误取率 ≤ **2%** | **长期存在**的缺陷 | **不依赖基线** |
| 业务正确性门禁 | 时间有效性 / 场景 / 标签 / 层级 / 环境边界 **零违规** | 硬错误 | **不依赖基线** |

"比上次没变差"不等于"够好"：一个本身就很弱的基线不发生退化时，相对门禁照样通过。
所以域外误召回率、首位误取率与业务约束都设了**绝对**判定。

业务正确性门禁的实测结果（伪向量模态）：

| 约束 | 检查次数 | 违规 |
| :--- | ---: | ---: |
| 场景约束 | 3914 | 0 |
| 层级约束 | 400 | 0 |
| 时间有效性 | 600 | 0 |
| 标签约束 | 159 | 0 |
| 环境边界 | 60 | 0 |
| 时间锚定召回 | 60 | 5（**判定暂停**：依赖语义召回，伪向量下量到的是语义能力缺失） |

**环境边界**有两条实现路径，职责不同：

- `memory_search` 没有结构化 `env` 参数，环境只能靠正文标记做词法区分，
  因此门禁断言的是"**环境匹配的经验必须排在其它环境的等价经验之前**"；
- Working 经验检索有结构化 `env` 参数，那里实现了**硬规则**：
  `strict_env = true` 时，环境不匹配的经验**直接不返回**（降权只是排序提示，
  Agent 仍可能误取；有安全后果的场景需要的是规则而不是排序）。

### 8.4 复现命令

```bash
# 质量门禁（相对基线）
cargo test --test eval_bench -- --nocapture
# 域外拒绝门禁 + 业务正确性门禁（绝对判定）
cargo test --test eval_bench test_ood_rejection_gate -- --nocapture
cargo test --test eval_bench test_business_constraint_gate -- --nocapture
# 阈值标定曲线
HUB_EVAL_CALIBRATE=1 cargo test --test eval_bench -- --ignored --nocapture
# 真实嵌入模型下的语义验收（必须同时打开语义要求开关）
HUB_EVAL_EMBED_ENDPOINT=https://…/v1/embeddings HUB_EVAL_EMBED_MODEL=bge-m3 \
  HUB_EVAL_REQUIRE_SEMANTIC=1 cargo test --test eval_bench -- --nocapture
# 重新冻结基线（伪向量模态）
HUB_EVAL_WRITE_BASELINE=1 cargo test --test eval_bench
```

### 8.5 本轮修正的两个实现缺陷

评测暴露、顺带修掉的两个真问题（都会影响检索质量，不是评测口径问题）：

1. **查询侧词元与文档侧不同源**：查询侧此前按**空白**切词并额外产出"整词"词元，
   而文档侧按标点切分并产出 1-gram/2-gram。于是 `os:linux` 这类带标点的词元、
   以及 3 字以上 CJK 整词，**在文档里根本不存在**——只进 IDF 分母不进分子，
   等于给所有查询的匹配度系统性打折，也让环境标记对打分完全不敏感。
   修正后查询侧与文档侧同源（`extract_terms` 复用文档侧分词器）。
2. **近期性维度无视参考时点**：查询钉住 `valid_at`（时间旅行）时，
   "距今多久"没有意义，但近期性仍按墙上时钟计算，把历史事实的分数压到阈值之下，
   导致时间锚定查询召不回它本该返回的历史版本。修正后以**参考时点**计算。

### 8.6 仍然待办（需要真实资源）

- **语义质量本身仍未验证**：所有数字都来自伪向量模态。接入真实嵌入服务后，
  必须重跑评测、重新标定阈值、重新冻结基线（届时 `embedder` 与 `semantic_ready`
  字段不同，门禁会自动提示不可比）。
- **域外查询集目前是"完全无关主题"**：真实域外查询往往只差一点点
  （同域但不同意图），这类"近邻域外"比现在的负例更难，必须补标。
- **Chat 认知抽取器仍是 Mock**：真实 LLM 抽取器接入前，Chat 流程的产出质量无法评估。
- **PostgreSQL 侧指标**（p50/p95、PG 词法行为）需在独立库上用
  `HUB_EVAL_PG=1 DATABASE_URL=…` 复跑；本轮 p50/p95 均为**内存存储**指标。

### 8.7 PostgreSQL 侧复跑（本次已完成）

之前"PostgreSQL 评测"从未被真正跑通过——本机没有 Docker 也没有 PostgreSQL，
PG 路径里还藏着两个只有在真库上才会暴露的问题（现已修复）：

1. **命名空间未注册**：PG 上 `memories.namespace` 有指向 `namespaces` 的外键，
   内存存储没有这层约束。评测写入直接撞外键。修法：用**带作用域**的 store 注册
   （`AccountScopedStore::ensure_namespace`）——注册未加账户前缀的名字等于没注册。
2. **PG 路径没套用生产配置**：它自己构造检索器、不带默认拒绝阈值，
   指标与内存侧不同口径。现已与内存路径统一（同一套权重 + 同一个默认阈值）。

（`memory_hub_test`，与生产库 `memory_hub` 完全隔离）复跑，10 个迁移按 CI 顺序用
