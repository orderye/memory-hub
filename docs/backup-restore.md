# 备份与恢复（当前约定）

本文是备份/恢复的**唯一现行说明**。历史报告（如 `upgrade/LIGHTWEIGHT_EXECUTION_REPORT.md`）
里的「最高 v4」「靠安全备份人工回滚」等结论已被本页取代。

对应代码：`crates/mem-core/src/backup_service.rs`（服务）、
`crates/store/src/postgres/backup.rs`（原子替换）、
`crates/worker/src/backup_job.rs`（定时快照）。

---

## 1. 格式版本

| 项目 | 当前值 |
|---|---|
| 负载版本 | **v6**（`BACKUP_PAYLOAD_VERSION = 6`） |
| 定时快照 | `backup-worker` / 内嵌模式与 `memory_backup_create` **同一 v6 载荷** |
| 校验 | SHA-256，按版本算法重算后与记录值逐版本比对 |
| 恢复端支持 | **v1–v6**；负载版本不在 `1..=6` 时明确拒绝，不静默跳过 |
| 旧二进制 | **不能恢复 v6**（只认 v1–v4/v5 的校验和）。降级前请保留新二进制，或先在新版本下完成恢复 |

v6 载荷包含 10 类实体：

```
entries · memory_versions · evidences · relations · tasks
experiences · experience_versions · task_experiences
coding_threads · coding_revisions
```

v5 及更早的载荷没有 `memory_versions`，读取时按空数组处理，校验和自然落到对应版本算法。

---

## 2. 校验与预检

恢复开始前依次执行（失败即返回，**不写任何业务数据**）：

1. 负载版本在 `1..=6` 内；
2. SHA-256 校验和与任一历史版本算法匹配；
3. 目标命名空间集合合法：非空、不是通配 `*`、不含账户作用域分隔符 `/`
   （防止伪造内部键把数据写进别的账户）；
4. 调用方对**每个**目标命名空间都有写权限。

第 3、4 步在 `dry_run` 阶段同样执行——预演必须回答"真正执行会不会被 ACL 挡住"，
而不是给出乐观结果。

---

## 3. 三种恢复模式

### `dry_run`

- 只读：逐个条目比对，统计 `created` / `updated` / `unchanged`；
- 不写条目、不写证据、不写关系、不建安全备份；
- 校验和/版本/目标范围/写权限任一不通过即报错。

### `merge`（默认）

- 保留快照内容；已存在的条目按快照内容推进一个版本，缺失的条目按快照新建；
- 单条**次要实体**失败（证据/关系/任务/经验/版本/关联/线程/修订）只计数并继续，
  汇总到 `RestoreReport.failed_*`，`partial=true`；
- **致命失败**（条目读写、存储错误）会按补偿账本回滚本轮全部改动：
  删除本轮新建的实体（含级联清理版本与关联），把被修订的条目按前像再修订回去；
- 回滚失败时返回**灾难恢复状态**错误（含受影响命名空间与原错误），
  绝不把失败报告成成功。

> 补偿的代价：被回滚的条目版本号会继续递增并留下一条历史。内容与关联都回到操作前，
> 但版本号不等于操作前的数字。

### `replace`

- 先为**每个**受影响命名空间创建安全备份；任一命名空间备份失败 → 立即中止，
  数据库一行都不删（`*` 全量备份按载荷里的真实命名空间逐个备份，不再静默跳过）；
- 清空与重建在**一次存储事务**内完成（PostgreSQL 实现为单事务；内存实现持锁原子替换），
  任一步失败整体回滚，不存在"删了但没写回"的中间态；
- 返回 `created` = 快照条目数，`safety_backup_ids` = 本次创建的全部安全备份。

## 4. 安全备份与自动回滚的真实边界

| 说法 | 是否成立 | 说明 |
|---|---|---|
| replace 前自动创建安全备份 | ✅ | 每个受影响命名空间一份，任一失败即中止 |
| replace 中途失败自动回到操作前 | ✅ | 原子事务回滚，不依赖安全备份 |
| merge 致命失败自动回滚 | ✅ | 补偿账本（删除本轮新建 + 前像回写） |
| merge 单条次要实体失败也回滚 | ❌ | 按设计只计数继续，报告 `partial=true`；需要绝对一致请用 `replace` |
| 补偿失败后自动兜底 | ⚠️ | 返回灾难恢复状态（含受影响命名空间与错误），需人工按安全备份恢复 |
| 跨账户恢复 | ❌ | 账户作用域由存储层强制；备份按 id 读取时也会校验归属 |

恢复审计（`append_audit`，动作 `memory_restore`）记录状态、模式与计数/安全备份 id；
审计写入失败只告警，不改变恢复结果，也不会回滚已完成的恢复。

---

## 5. 仍未解决的恢复风险

1. **merge 的部分失败不是原子的**：次要实体失败后不会回滚（与历史行为一致），
   调用方必须检查 `partial` / `failed_*`。
2. **没有跨实体单事务的 merge**：`MemoryHubStore` 是 12 个 trait 的组合，逐实体写入；
   补偿是"等效回滚"，不是数据库事务语义。
3. **补偿依赖外键级联**：经验版本与任务-经验关联没有独立的删除接口，靠
   `on delete cascade` 清理；若未来新增无级联的子表，需要同步更新补偿顺序。
4. **大命名空间 replace 会在一个事务里完成整表删除+重建**，
   锁持有时间与数据量成正比，生产建议在维护窗口执行。
5. **v6 之前的旧二进制无法读取新快照**：降级前必须完成恢复或保留新二进制。

## 6. 常用命令

```bash
# 创建快照（MCP 工具）
memory_backup_create  { "namespace": "team-a" }
# 预演
memory_restore        { "backup_id": "<uuid>", "mode": "dry_run" }
# 增量恢复
memory_restore        { "backup_id": "<uuid>", "mode": "merge" }
# 整体替换（写前自动安全备份）
memory_restore        { "backup_id": "<uuid>", "mode": "replace" }
```

恢复完成后请复核 `RestoreReport` 的 `partial` 与 `failed_*`：
`partial=false` 且各 `failed_*` 为 0 才代表完整成功。整轮被回滚时不会返回报告，
而是返回错误（错误信息会写明"已按补偿账本回滚到操作前状态"，审计记录同样落这条结论）。
