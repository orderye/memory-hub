# 多智能体长期记忆服务设计（记忆中枢 v2）

> 版本：v2.0（2026-10-11） · 替代历史版本「记忆中枢系统设计与技能框架 v1.0」
> 本版为**重做设计**：彻底移除六技能框架（天理与人欲 / 国民总记忆 / 知守与知行 / 天心即民心 / 我命即天命 / 如梦亦如幻）、量表校准、脑筋急转弯式的反迎合判定；项目重新定位为**多智能体长期记忆的存储、备份、整合 MCP 服务**。
> 实现：Rust workspace，201 个测试全绿；生产部署 PostgreSQL 15 + pgvector。

---

## 1. 定位与边界

**做什么（三件事）：**

1. **存储**：多 Agent 共享的长期记忆条目。主体是 Agent（OAuth 2.1 客户端），记忆按命名空间隔离；首次写入某命名空间的 Agent 自动成为其 owner。
2. **备份**：命名空间（或全量）不可变快照 + SHA-256 校验和 + 保留策略 + 三种恢复模式。
3. **整合**：多 Agent 并发写入产生的重复/冲突的识别与归并——只生成提案，由 Agent 显式裁决，保留完整溯源。

**不做什么：**

- 不做技能框架、行为规范、量表校准、反迎合判定（v1 全部移除）；
- 不做生成式推理——检索返回条目，怎么用是调用方自己的事；
- 不做单用户个人画像中心——没有"用户中心"，只有 Agent 注册与命名空间授权。

## 2. 核心概念

| 概念 | 说明 |
| :--- | :--- |
| **Agent** | 调用方主体，与 OAuth 客户端一一对应（`agent_id`）。可为服务、助手或 Worker |
| **Namespace** | 记忆的逻辑隔离空间（如 `default`、`team-x`）。行级隔离的根本维度 |
| **MemoryEntry** | 一条记忆：正文 + 分类 + 标签 + 元数据 + 向量 + 置信度 + 版本 + 生命周期状态 |
| **key** | 命名空间内唯一的业务键；提供时 `put` 走 upsert（修订而非新建） |
| **MemoryVersion** | 每次内容修订追加一条的历史记录（备份与审计的事实来源） |
| **BackupRecord** | 快照：某命名空间全部条目的不可变副本 + 校验和 |
| **IntegrationProposal** | 整合提案：duplicate（高相似）或 conflict（同 key 不同内容） |
| **NamespaceGrant** | 命名空间级读/写授权；owner 隐式拥有，可通过 `memory_grant` 分享 |

### 2.1 记忆条目生命周期

```
put ──▶ Active ──delete──▶ Archived（软删除，仍参与备份）
              │
              └──merge──▶ Merged（指向幸存条目 merged_into，保留溯源）
```

过期（`expires_at` 到点）由 `backup-worker` 归档为 Archived，并记入版本历史。

## 3. 领域模型（mem-core/domain.rs）

```rust
MemoryEntry {
  id: Uuid,
  namespace: String,            // 隔离维度
  key: Option<String>,           // 业务键（namespace 内唯一）
  kind: Fact|Preference|Episode|Note|Skill|Procedure,
  content: String,               // ≤ 8192 字符
  tags: Vec<String>,             // ≤ 32 个，单个 ≤ 64 字符
  metadata: serde_json::Value,   // ≤ 16KB（序列化后）
  embedding: Option<Vec<f32>>,   // 归一化；mock/HTTP 两种来源
  embedding_model: Option<String>,
  source_agent: AgentId,         // 写入者
  confidence: f32,               // [0,1]，参与检索加权
  status: Active|Archived|Merged,
  version: i64,                  // 每次内容修订 +1
  expires_at: Option<DateTime<Utc>>,
  merged_into: Option<Uuid>,
  created_at, updated_at: DateTime<Utc>,
}
```

## 4. 数据模型（crates/store/migrations）

| 表 | 职责要点 |
| :--- | :--- |
| `agents` | Agent 注册（DCR）：密钥散列、重定向 URI、scope 上限 |
| `namespaces` | 命名空间注册：owner_agent 外键级联 |
| `namespace_grants` | (namespace, agent_id) → can_read/can_write；支持通配 `*` |
| `memories` | 记忆主表；`unique(namespace, key)` 支撑 upsert；HNSW 向量索引 + `to_tsvector('simple')` GIN 索引 + 分页复合索引 |
| `memory_versions` | (memory_id, version) 主键；写入幂等（`on conflict do nothing`） |
| `memory_backups` | 快照：payload jsonb + checksum + retain_until |
| `integration_proposals` | 提案：member_ids uuid[]、suggested_survivor、status |
| `refresh_tokens` / `confirm_tokens` | OAuth 2.1 持久化入口 |
| `idempotency_keys` / `rate_limit_buckets` | 幂等与跨副本限流 |
| `events` / `audit_log` | 只追加审计（`audit_writer` 角色被 `revoke update, delete, truncate`） |

命名空间删除级联清除其记忆、授权与提案；Agent 删除级联其授权。

## 5. 服务层（mem-core）

三个服务 + 一个访问判定器，全部依赖 trait 抽象（`MemoryStore` / `BackupStore` / `IntegrationStore` / `GrantStore` / `AgentStore` / `Embedder` / `Retriever` / `Clock`），PostgreSQL 与内存实现可互换：

### 5.1 MemoryService（存取）

| 方法 | 语义要点 |
| :--- | :--- |
| `put` | 先 `ensure_namespace`（首写者成为 owner 并获授权）再校验写权限；同 key upsert；生成嵌入；记版本 |
| `get` | id 或 key 二选一；命名空间不对即 NotFound |
| `update` | 补丁式修订；内容变化触发重嵌入；版本 +1 |
| `delete` | 软删除 → Archived；重复删除报错（防误判状态机） |
| `search` | 委托注入的 Retriever（混合检索），未注入时退化为纯向量加权 |
| `list` | 游标分页 `(updated_at, id) <` 复合键，排序稳定 |
| `stats` | 按状态/类型/Agent 分布 + 24h 到期计数 |
| `history` | 条目版本历史（按版本升序） |

**访问控制两层：** token scope（能不能做这类操作）+ GrantStore（能对哪个命名空间做）。`ensure_namespace` 只在命名空间**新建**时授予 owner 权限——防止后来者借 ensure 之名放权。

### 5.2 BackupService（备份）

| 方法 | 语义要点 |
| :--- | :--- |
| `create` | 快照 namespace（或全量 `*`）全部条目（含 archived/merged）；SHA-256 校验和 |
| `list` | 逐份校验读权限；全量快照仅通配读授权可见 |
| `restore` | 恢复前重建校验和，**不匹配即拒绝**；`dry_run` 只报差异；`merge` 覆盖变化条目；`replace` 先为每个受影响命名空间创建安全备份（`restore-safety:*`）再清空重建 |
| `prune` | 每命名空间保留最新 N 份；超 TTL 的旧快照淘汰（至少保留 1 份） |

### 5.3 IntegrationService（整合）

| 方法 | 语义要点 |
| :--- | :--- |
| `scan` | 同 kind 且嵌入余弦 ≥ 阈值 → duplicate（并查集聚类）；同 key 内容不同 → conflict；已有 open 提案的组跳过（幂等，不刷屏）；`dry_run` 不落库 |
| `resolve(merge)` | 幸存条目保留并吸收全部成员标签；其余成员 → Merged 并写入 `merged_into`；提案关闭 |
| `resolve(dismiss)` | 保留分立，仅关闭提案 |
| `expire_stale` | 归档到期条目（worker 调用；PG 侧单条 CTE 完成归档 + 版本历史） |

## 6. 检索（retrieval）

```
query ─┬─ FTS 路：text_contains → 存储层 to_tsvector(simple) GIN
       └─ 向量路：embed(query) → HNSW <=> 余弦近邻
                        │  并行 + 软超时（超时降级列表召回）
                        ▼
        按 id 合并去重 → 五维加权（sim/kw/conf/rec/fresh，权重可配且和必须为 1）
                        ▼
        MMR 重排（λ 可配；嵌入缺失项相互相似度按 0）
```

## 7. 鉴权（OAuth 2.1）

- **Scopes**：`memory:read`（读）/ `memory:write`（写+整合）/ `memory:admin`（备份/恢复/授权）。
- **访问令牌**：HS256 JWT，`sub = agent_id`，`aud = 本服务资源 URI`（RFC 8707 严格绑定，拒跨服务令牌），载荷内嵌 `grants: Vec<NamespaceGrant>`；资源服务器**离线验签**。
- **三种授予**：
  - `client_credentials`：机器 Agent 主路径（需注册时提供密钥；不发刷新令牌）；
  - `authorization_code + PKCE S256`：Agent 控制台/代为行动场景（授权码 300s 一次性，redirect_uri 白名单校验）；
  - `refresh_token`：Token Family 轮换 + 重放检测（重放即吊销整族）。
- **DCR（RFC 7591）**：`POST /oauth/register` 自助注册；scope 上限在注册期裁剪，令牌签发时再次钳制。
- **元数据**：RFC 8414 授权服务器元数据 + RFC 9728 受保护资源元数据。

## 8. MCP 协议面

- 版本协商：`2026-07-28`（主）/ `2025-11-25`（回退）。
- 工具错误在 200 内以 `isError=true` + 标准错误码对象（`E_*`）表达；传输层错误用 JSON-RPC 码（32001 认证 / 32002 权限 / 32003 限流 / 32005 冲突）。
- 每个工具携带 `readOnly` / `destructive` / `idempotent` 标注；schema 全部关闭 `additionalProperties`。
- 安全纵深：Origin 白名单（仅放行非 GET 方法）→ 请求体上限 → Bearer 校验 → 每 Agent 令牌桶限流（fail-open）→ scope 强制 → 服务内 ACL。

## 10. 失效模式与硬防御

| 场景 | 行为 |
| :--- | :--- |
| Agent 无 namespace 授权 | 拒绝（scope + ACL 双重判定） |
| 后来者对已存在命名空间 ensure | 不授予任何权限 |
| 备份负载被篡改 | 恢复前校验和不匹配即拒绝 |
| replace 恢复中途失败 | 已先建安全备份，可再恢复 |
| 重复/冲突写入 | 只生成提案，绝不静默删数据 |
| refresh 重放 | 吊销整族令牌 |
| 跨服务令牌透传 | aud 严格绑定拒绝 |
| 嵌入服务故障 | 写入降级（无向量）+ 检索降级 FTS |
| 检索超时 | 软超时降级列表召回 |
| 限流存储故障 | fail-open（可用性优先），多副本用 PG 桶保持一致 |

## 13. 部署形态与生产级资源管控

- **单副本编排**：三进程 + PostgreSQL 15 + pgvector（`docker-compose.yml` 默认）。
- **水平扩展**：`mcp-server` 可多副本（无状态、离线验签）；限流桶共享 PostgreSQL；`auth-server` 的授权码/刷新令牌默认内存（多副本需替换存储）；`backup-worker` 单实例（cron 到点即跑，幂等安全）。
- **资源与并发边界（P0+P1 落地）**：
  - **容器配额（Cgroups）**：编排层声明 `limits.memory` 与 `limits.cpus`，杜绝整机 OOM-Killer；
  - **连接池收敛**：`HUB_DB_MAX_CONNECTIONS` 控制单 Pod 连接上限（5~10），PG 启动参数调大至 `max_connections=200` 并针对 pgvector 调优 `shared_buffers` / `maintenance_work_mem`；
  - **线程对齐**：支持 `TOKIO_WORKER_THREADS` 环境变量与容器 CPU 限制 1:1 对齐，防止跨核争抢；
  - **内存分配器**：二进制引入 `jemalloc`（Feature `jemalloc`），在 Linux 容器长期运行态抑制内存碎片；
  - **CPU 密集计算隔离**：检索打分与 MMR 矩阵计算移入 `tokio::task::spawn_blocking`，保障异步 I/O 反应堆零饥饿。
