# 记忆中枢（Memory Hub）工程实施计划

**版本**：v1.0  
**基准文档**：`记忆中枢系统设计与技能框架（开发交付版 v1.0）`  
**技术栈**：全栈 Rust（Cargo Workspace） + PostgreSQL 15 (含 pgvector) + Streamable HTTP / stdio (MCP 协议) + 自建 OAuth 2.1 授权服务器  
**执行周期**：18 周（P1 最小闭环 9 周、P2 完整框架 6 周、P3 治理与规模 3 周）

---

## 1. 实施原则与工程基准

1. **唯一权威性**：系统设计与规格以交付版设计文档第 17~19 节及附录 C 为唯一技术依据。开发中遇到未定事项严格依据第 16 节的**默认假设**推进，不中断停工，所有疑问记录于 `docs/questions.md`。
2. **纯 Rust 统一架构**：MCP 核心服务、自建授权服务器、用户中心、编审工作台、离线分析与参考客户端全量采用 Rust 语言构建，依托 Trait 进行模块解耦，禁止在线链路引入任何非必需生成模型。
3. **数据红线绝对防御**：
   - 绝不持久化对话原文；`hub_check.draft` 确定性规则校验完毕后立即释放内存，禁止落库与记入日志。
   - 身份证、银行卡等禁存类别强制前置过滤并返回 `E_POLICY_BLOCKED`。
   - 日志输出严格脱敏（仅留 trace ID、方法、认证主体、耗时、状态码）。
4. **契约驱动与并行协作**：以 `hub-core` 定义的公共 Trait（`MemoryStore`, `Embedder`, `Retriever`, `PackRegistry`, `RuleEngine`）为契约边界，通过 Mock 实现各流水线解耦并行推进。

## 3. 22 个工作包（WP-01 ~ WP-22）分解与实施规格

### WP-01：工程工作区、CI 与 common 基础库
- **归属 Crate**：`common`
- **前置依赖**：无
- **主要交付物**：
  - 根目录 `Cargo.toml` 工作区配置（统一依赖版本与 `forbid(unsafe_code)` 检查）。
  - `common/src`：统一错误类型 `HubError`、上下文追踪、配置加载（env/yaml 强校验）、脱敏日志 `tracing` 配置、Prometheus 指标收集桩。
  - CI 配置（GitHub Actions / 本地构建脚本）：`cargo fmt`, `cargo clippy -- -D warnings`, `cargo-deny`（合规许可证与源检查）, `cargo-audit`（漏洞扫描）。
- **验收标准**：本地与 CI 环境全绿构建，配置缺少必填项时拒启并打印安全提示。

### WP-02：领域类型与服务接口定义
- **归属 Crate**：`hub-core`
- **前置依赖**：WP-01
- **主要交付物**：
  - 核心领域模型（`MemoryItem`, `Layer`, `Provenance`, `Sensitivity`, `UsePolicy`, `ItemStatus` 等）。
  - 服务抽象 Trait：`ContextService`, `ObserveService`, `CheckService`, `FeedbackService`, `MemoryAdminService`。
  - 基础设施抽象 Trait：`MemoryStore`, `Embedder`, `Retriever`, `PackRegistry`, `RuleEngine`, `Clock`, `AuditSink`。
- **验收标准**：`hub-core` 保持纯领域逻辑，禁止引入任何外部 Web 框架（如 axum）、DB 客户端（如 sqlx）或 MCP SDK。

### WP-03：数据持久化与迁移（PostgreSQL + pgvector）
- **归属 Crate**：`hub-store`
- **前置依赖**：WP-02
- **主要交付物**：
  - `sqlx` 迁移脚本（设计文档 17.3 定义的所有表）：`users`, `oauth_clients`, `consents`, `refresh_tokens`, `confirm_tokens`, `memory_items`, `memory_evidence`, `hypotheses`, `events`, `idempotency_keys`, `norm_rules`, `skills`, `pack_sets`, `audit_log` 等。
  - 向量扩展初始化（`vector(1024)` HNSW 索引、gin 文本索引）。
  - 只追加表权限控制（`events`, `audit_log` 撤销写角色 update/delete 权限）。
  - 行级租户隔离及带 `user_id` 的 Store 实现。
- **验收标准**：多租户越权查询集成测试、只追加表防篡改测试通过。

### WP-04：记忆管理与状态生命周期算法
- **归属 Crate**：`hub-core`
- **前置依赖**：WP-02, WP-03
- **主要交付物**：
  - 算法 B：置信度更新（命中升权、未命中降权、否定淘汰）与各层时间常数衰减计算（注入 `Clock`）。
  - 算法 C：推断条目升格规则校验（$n_{obs} \ge 3$, 场景数 $\ge 2$, 跨度 $\ge 7$ 天, 置信度 $\ge 0.7$）。
  - 算法 G：幂等写入拦截（24h 窗口去重）。
  - 算法 H：删除级联逻辑（条目删除级联证据与向量、用户注销全量擦除与事件匿名化）。
- **验收标准**：基于属性测试（proptest）验证置信度在 $[0, 1]$ 严格收敛；级联删除在 DB 中无孤儿记录残留。

### WP-05：嵌入模型适配器（hub-embed）
- **归属 Crate**：`hub-embed`
- **前置依赖**：WP-02
- **主要交付物**：
  - `MockEmbedder`：供本地测试与离线构建，生成确定性伪向量。
  - `OnnxEmbedder`：基于 `ort` 运行时加载本地模型，实现前向推理、池化与 L2 归一化。
  - 提示词文本清洗与向量缓存（结合场景标签哈希）。
- **验收标准**：Mock 与 ONNX 实现均通过同一组契约测试（维度一致性、归一化长度 = 1.0）。

### WP-06：多路混合检索引擎
- **归属 Crate**：`hub-retrieval`
- **前置依赖**：WP-03, WP-05
- **主要交付物**：
  - 过滤流水线：用户隔离、ACL 读权限、未过期、非 blocked 状态、未成年模式过滤。
  - 双路召回：全文检索 Top-20 + pgvector 余弦相似度 Top-20。
  - 综合排序打分公式计算：
    $$\text{score} = 0.40 \cdot \text{sim} + 0.20 \cdot \text{kw} + 0.15 \cdot \text{conf} + 0.10 \cdot \text{rec} + 0.15 \cdot \text{prov}$$
  - MMR 多样性重排算法（$\lambda = 0.7$）。
- **验收标准**：单用户检索延迟测试 ≤ 50ms；检索评测集建立基础 Recall@10 基线。

### WP-07：规范包管理与原子热替换（hub-packs）
- **归属 Crate**：`hub-packs`
- **前置依赖**：WP-02
- **主要交付物**：
  - 规范包与量表模型反序列化（YAML/JSON Schema）。
  - `PackRegistry` 实现：内存级 `ArcSwap<PackSet>` 原子替换，支持基于 `user_id` 哈希分桶灰度。
  - 核心锁校验：装配与加载时严格校验 `core_hash`，若底线硬规则被篡改，立即拒绝服务并告警。
- **验收标准**：在持续读请求压测下触发版本热替换，吞吐无毛刺、零请求报错；篡改测试 100% 拦截。

### WP-08：智能包装配器（Assembler）
- **归属 Crate**：`hub-core`
- **前置依赖**：WP-04, WP-06, WP-07
- **主要交付物**：
  - 装配调度流水线（算法 E）：权限检查、`minor_mode` 保护（个人记忆清空仅下发基础规范）、规则筛选排序、关系策略紧凑表下发。
  - 冲突检测与包档位决策：检测 C1~C6 冲突标签或高风险标签，自适应选择紧凑包（规范 ≤ 8 条）或完整包。
  - `do_not_mention` 隔离（`never_mention` 绝不进入记忆正文）。
  - 软超时熔断降级：超过 `latency_budget_ms` 时生成 `degraded: true` 的兜底包返回。
- **验收标准**：紧凑包 token 预算精确控制在客户端预算内；注入超时时平滑降级，零 panic。

### WP-09：MCP 服务协议层与工具实现
- **归属 Crate**：`hub-mcp`
- **前置依赖**：WP-08
- **主要交付物**：
  - Streamable HTTP 与 stdio 传输层实现（基于官方 SDK `rmcp` 构建反腐层）。
  - 工具能力暴露：`hub_context`, `hub_observe`, `hub_check`, `hub_feedback`, `hub_memory_*`。
  - JSON Schema 2020-12 严格校验（`additionalProperties: false`）。
  - 双模响应生成：返回结构化 `structuredContent`，并在普通 `content` 中携带兼容 JSON 文本。
  - 发现接口：实现 `server/discover` 并向下兼容旧版 `initialize`。
- **验收标准**：通过官方 MCP Inspector 全量测试；协议层无状态，双实例负载均衡行为一致。

### WP-10：资源服务器授权拦截（hub-authz）
- **归属 Crate**：`hub-authz`
- **前置依赖**：WP-02
- **主要交付物**：
  - OAuth 2.1 访问令牌校验（JWT / 签名验签、有效期、发行者与受众校验）。
  - 受保护资源元数据公布（RFC 9728 端点）。
  - 资源指示符校验（RFC 8707）：拒绝其他受众的令牌，杜绝跨服务令牌透传。
  - Scope 细粒度拦截（`memory:context`, `memory:write`, `memory:manage`）与分步授权提示。
- **验收标准**：非法/过期/错配受众令牌均拒绝并返回标准化 401 及 RFC 9728 指引。

### WP-11：自建授权服务器核心（as-core）
- **归属 Crate**：`as-core`
- **前置依赖**：WP-03
- **主要交付物**：
  - OAuth 2.1 规范核心：授权码流（强制 S256 PKCE），禁止密码模式与隐式模式。
  - 令牌生命周期：短期 Access Token（15 分钟），Refresh Token 强制轮换（Rotation）与重放检测（重放时作废整个 Token 族）。
  - 授权确认令牌机制（`confirm_token` 120 秒有效，破坏性操作二次鉴权）。
  - 境内 KMS/安全密匙对接，敏感比对常量时间执行。
- **验收标准**：PKCE 攻击防御测试通过；Refresh Token 重放检测测试 100% 触发作废。

### WP-12：用户中心与同意授权页（as-web）
- **归属 Crate**：`as-web`
- **前置依赖**：WP-11
- **主要交付物**：
  - 服务端渲染轻量前端（axum + 模板引擎）。
  - 单独同意页：细粒度展示读取/写入层，敏感层独立授权选项，记录不可篡改的同意回执哈希。
  - 用户控制中心：已授权助理管理、授权一键撤销、访问审计流水、个人记忆导出（JSON/CSV）与账户注销。
- **验收标准**：撤销授权后级联清除助理凭据并通知相关缓存失效；导出包带有效期安全链接。

### WP-13：规则引擎与冲突消解器（hub-rules）
- **归属 Crate**：`hub-rules`
- **前置依赖**：WP-02
- **主要交付物**：
  - 纯函数确定性校验：词表与模式匹配（基于 `regex` / `aho-corasick`）。
  - 冲突消解执行器（算法 F）：查询 C1~C6 预编译消解表，未命中场景下发保守策略（`hedge`）并记录 `uncovered_conflict`。
  - 迭代轮次硬限制（最多 2 轮退出，防止振荡）。
- **验收标准**：规则匹配基准测试 < 1ms；复杂冲突组合消解输出确定可预测。

### WP-14：Skill 框架与核心锁集成
- **归属 Crate**：`hub-packs`, `hub-rules`
- **前置依赖**：WP-07, WP-13
- **主要交付物**：
  - Skill Manifest 校验器（版本依赖、签名校验、阶段灰度规则）。
  - 六 Skill 声明式包装配整合（天心即民心、天理与人欲、我命即天命、知守与知行、如梦亦如幻、国民总记忆【开关关闭】）。
  - 关系规范集三阶段流水线实现（差序格局判定 $\rightarrow$ 人情面子策略 $\rightarrow$ 礼貌准则表达）。
  - 核心锁锁定规则（天心底线规则、合规底线规则、G1/G2 硬门、`never_mention` 防护）强制注入。
- **验收标准**：任意 Skill 卸载或崩溃时，核心锁规则依然稳定存在；非核心 Skill 灰度切换正常。

### WP-15：自检量表评估与反馈处理（hub_check / hub_feedback）
- **归属 Crate**：`hub-core`, `hub-mcp`
- **前置依赖**：WP-09, WP-13
- **主要交付物**：
  - `hub_check`：校验自评分格式，执行硬门 G1/G2（涉及国民总记忆时启用 G3）确定性复验；草稿内存校验后立即释放。
  - `hub_feedback`：接收用户反馈（采纳、拒绝、纠错、申诉），生成脱敏事件记入流表。
  - 硬门违反率与反迎合指标监控埋点。
- **验收标准**：草稿不留存自动化验证（堆内存与日志扫描无草稿字符串）；反馈处理全量幂等。

### WP-16：行为回流与循环一致性引擎
- **归属 Crate**：`hub-core`
- **前置依赖**：WP-04, WP-09
- **主要交付物**：
  - `hypotheses` 状态流转管理（open $\rightarrow$ matched / missed / expired）。
  - 循环一致性自动对比：对比真实后续行为事件与先验预测反应，命中则提高置信度，未命中则衰减。
  - 边际判定计算（Top-1 与 Top-2 差距 $< 0.15$ 时标记 `ambiguous: true`）。
- **验收标准**：模拟行为序列驱动假设自动升降级端到端测试通过。

### WP-17：离线任务工作进程（offline-worker）
- **归属 Crate**：`offline`
- **前置依赖**：WP-04, WP-16
- **主要交付物**：
  - 每日记忆巩固作业：执行批量时间衰减、退休低置信条目、物理删除超期 30 天的废弃条目。
  - 聚类与候选生成：对未覆盖冲突、失败案例进行向量聚类，输出新规则候选至审批池。
  - 作业幂等性保证与运行日志。
- **验收标准**：大规模数据集回放测试通过，作业中断后重新执行无副作用。

### WP-18：评测平台与量表校准系统
- **归属 Crate**：`eval`
- **前置依赖**：WP-08, WP-15
- **主要交付物**：
  - 场景集自动化运行器（关系类型 $\times$ 地位差 $\times$ 场合，含反例场景集）。
  - 量表参数校准管道（实现 7.4 节流程：成对偏好标注映射、单调回归拟合、反迎合下限约束）。
  - 消融实验自动化测试套件（模块级与 Skill 级逐一消融评测）。
- **验收标准**：针对示例数据集输出完整的 Recall@k、遵循率、迎合率、Tau 阈值推荐报表。

### WP-19：参照标准客户端（ref-client）
- **归属 Crate**：`ref-client`
- **前置依赖**：WP-09

## 5. 核心架构关键技术实施方案

### 5.1 存储与租户隔离落地
- **数据库技术**：PostgreSQL 15+，启用官方扩展 `vector` 与全文检索分词器。
- **多租户安全**：所有对 `memory_items` 的 SQL 查询必须带 `WHERE user_id = $1` 条件；数据库层启用行级安全（Row Level Security, RLS）策略，应用服务绑定特定上下文变量作为第二道纵深防御。
- **审计与事件存储**：创建专用数据库用户 `audit_writer`，仅授予 `events` 与 `audit_log` 表的 `INSERT` 权限，撤销 `UPDATE`、`DELETE`、`TRUNCATE` 权限，确保物理级只追加（Append-only）。

### 5.2 统一 MCP 服务（hub-mcp）
- **通信模型**：生产环境默认运行 Streamable HTTP 远程传输，面向公网配合反向代理与 TLS；开发与本地集成同时提供 stdio 桥接模式。
- **无状态架构**：服务实例完全无粘性，不维护会话内存。客户端携带 `conversation_id` 与 `turn_id`。
- **防腐层（ACL & Mapping）**：将底层 MCP SDK 的数据结构与领域实体隔离开，屏蔽 MCP 协议版本升级带来的变动；将业务异常准确映射为标准错误码（17.6）。
- **软超时机制**：装配管道内嵌 `tokio::time::timeout`。当耗时接近 `latency_budget_ms` 时，立即中止向量计算与高级规则匹配，装配最小核心硬规则与最新记忆，返回 `degraded: true`，确保助理 LLM 不被中枢延迟阻塞。

### 5.3 自建 OAuth 2.1 授权服务器（as-core & as-web）
- **协议栈**：OAuth 2.1 + OIDC。
- **安全加固**：
  - 授权码模式强制使用 S256 PKCE，不提供 Client Secret 给公开客户端。
  - 颁发短期 Access Token（JWT，RS256 签名，15 分钟），载荷带 `aud` 严格限定于记忆中枢资源标识（RFC 8707），`iss` 标明授权服务（RFC 9207）。
  - Refresh Token 存哈希值，每次刷新强制轮换新 Token；若检测到已使用旧 Token 发起请求，立即注销整个关联 Token 族并告警。
- **同意回执（Consent Receipt）**：用户在授权界面确认读写层与敏感层后，生成内容摘要 SHA-256，与时间戳、条款版本一同签署并落库保存，支持后续合规审计。

### 5.4 规则引擎与核心锁防篡改
- **核心锁结构**：
  ```rust
  pub struct CoreLock {
      pub rules: Vec<RuleId>,
      pub expected_hash: String,
  }
  ```
- **校验算法**：在服务启动、每次规范包热加载以及每次 `Assembler::context` 调用前，对锁定在核心集合内的规则条目（天心硬规则、合规规则、G1/G2 硬门）按规则 ID 排序并序列化计算 SHA-256 哈希。若与系统预设哈希不匹配，立即抛出 `HubError::Internal` 熔断拦截，防止由于数据配置错误或非法篡改导致合规底线失效。
